# M2.1 – AstronoDiag & Deterministic GroundTruth (Milestone Documentation)

## 1. Overview

Milestone M2.1 marks the successful completion of the first Level 1 readiness step of the AstronoSphere pipeline.

The focus of this milestone was:

* Expansion of the experiment space via structured mesh generation
* Introduction of a deterministic diagnostic system (AstronoDiag)
* Elimination of implicit data manipulation (no clipping)
* Establishment of full transparency in GroundTruth generation

The result is a robust, deterministic, and fully auditable GroundTruth pipeline.

---

## 2. Key Achievements

### 2.1 Deterministic GroundTruth Generation

The EphemerisFactory now follows a strict rule:

```text
GroundTruth = f(Core)
```

* No dependency on CatalogNumber
* No hidden corrections or adjustments
* Identical input → identical output (bitwise)

---

### 2.2 Removal of Clipping

Previous behavior:

* Experiments partially outside Horizons validity were automatically clipped
* This introduced non-deterministic and non-transparent behavior

New behavior:

```text
NO CLIPPING
```

* Out-of-range → rejected
* Partial overlap → rejected
* All decisions explicitly recorded via diagnostics

---

### 2.3 AstronoDiag Module

A new module `AstronoDiag` was introduced.

Responsibilities:

* Centralized diagnostic handling
* Deterministic error classification
* Structured output for all failure cases

---

## 3. Diagnostic System

### 3.1 Code System (ASC.FMI)

| Code    | Meaning                  |
| ------- | ------------------------ |
| 030.003 | Maturity != Released     |
| 030.005 | ProviderRangeViolation   |
| 030.006 | RequestFailed (Horizons) |
| 030.007 | ParseFailed              |

---

### 3.2 Processing Rules

Exactly one outcome per experiment:

```text
IF Maturity != Released
    → 030.003

ELSE IF outside ProviderRange
    → 030.005

ELSE IF request fails
    → 030.006

ELSE IF parse fails
    → 030.007

ELSE
    → Dataset generated
```

---

### 3.3 Diagnostic Output

Location:

```text
03_GroundTruth/
  DiagMessages/
    Run/
    LastRun/
```

Filename format:

```text
DiagMsg__<CatalogNumber>__<Human>__<Code>.json
```

---

## 4. Run / LastRun Behavior

Unified rule for GroundTruth and Diagnostics:

```text
Run → copied to LastRun
Run → cleared
LastRun → NEVER deleted
```

Properties:

* Full determinism verification
* Historical accumulation of results
* Overwrite allowed for identical filenames

## 6. Important Observations

### 6.1 Duplicate Experiments

Multiple experiments can produce identical GroundTruth datasets:

* Same Core → same Dataset
* Files overwrite intentionally

This is correct behavior:

```text
GroundTruth is Core-based, not CatalogNumber-based
```

---

### 6.2 Single-Point Edge Case

Case:

```text
StartJD == StopJD
```

Result:

* Horizons rejects request
* Correct classification: 030.006

Interpretation:

* Not invalid physics
* But unsupported request type (batch model)

---

## 7. Data Integrity Principle

```text
Never modify experiment data implicitly.
Always expose inconsistencies via diagnostics.
```

This principle is now fully enforced.

## 8. Known Limitations

* No support for single-point Horizons requests
* No aggregation or summary diagnostics
* No lifecycle tracking across runs
* JSON formatting not preserved by migration scripts
